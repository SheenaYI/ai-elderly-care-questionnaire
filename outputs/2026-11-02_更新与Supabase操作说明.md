## 需要队友执行什么 SQL？（尚未执行）

原因：0005 原函数要求所有老人答卷都填三项排序，新页面允许只分100分，两者必须同步。
文件：supabase/migrations/0006_v23_weight_mode.sql。

影响范围：仅 submit_survey_v23(jsonb) 中一条排序校验条件。100分模式允许空排序；仅排序模式仍要求三项完整且不同。若原始答卷有排序，仍校验合法性。
不新增或删除表，不更新旧答卷，不改RLS、不增加数据库权限。修订标识可直接使用已有JSONB字段，无需新列。
SQL通过读取现有函数定义、精确替换已知条件完成更新；如函数与预期不同则中止。可重复运行。必须先执行过0005。

操作流程：

1. 研究负责人先审查并确认迁移。未经确认不要执行。
2. 队友进入正确 Supabase 项目 → SQL Editor。先查看并保存 `select pg_get_functiondef('public.submit_survey_v23(jsonb)'::regprocedure);` 的结果作为函数备份。
3. 打开上述0006文件，复制全部SQL到Editor，确认项目无误后运行。
4. 用文件末尾只读查询确认新条件、函数权限仍正确。不修改任何RLS。
5. 在测试项目或本项目 test 样本渠道验证老人“100分且无排序”、老人“仅排序且分数为空”、照护者正常提交与研究员读取。测试渠道记录不可计入正式样本。不删除历史数据。
6. 确认后再部署网页和Netlify函数，勿只部署前端遗漏服务端校验与导出修改。

环境变量无需新增；继续使用已有Supabase/Netlify配置，不把service_role密钥放入前端。
