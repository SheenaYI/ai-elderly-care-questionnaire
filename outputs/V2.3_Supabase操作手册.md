### 第二步：登录Supabase，确认是原项目，再备份

1. 打开 [Supabase Dashboard](https://supabase.com/dashboard)，使用保管原项目的账号登录。
2. 在项目列表点击现有养老问卷项目。核对项目名称、浏览器地址中的项目ID，与目前Netlify使用的是同一个项目。**不要点击 New project。** 如果看不到项目或没有编辑权限，先联系项目管理员，不要建替代项目。
3. 左侧点击 **Database → Backups**，查看项目可用备份，记录最新备份时间。只查看，不点Restore/恢复；恢复备份不属于这次升级。
4. 若当前套餐没有可用备份，按团队已有的数据库导出方式做完整逻辑备份。Table Editor里选择 `public` → 打开旧数据表 → 表菜单 `…` → **Download CSV / Export as CSV**，可作为数据额外副本；菜单名称可能随界面版本不同。导出前取消筛选并核对行数，避免只导出当前页。**CSV不是完整数据库结构/权限备份，不能当作完整备份。** 不确定如何备份时先停止，让负责数据库的同学协助。
5. 备份存团队私有位置，不上传GitHub，不在截图中暴露密钥或真实答卷。继续保留现有研究员账号和管理员白名单，不删除任何表。

### 第三步：只读检查项目是否具备升级条件

点击左侧 **SQL Editor → New query / New Query（新建查询）**；若已启用新版Explorer，入口可能显示为Explorer，找到SQL查询编辑区即可，不需要开启新功能。

点击编辑区，粘贴下面这段SQL，点 **Run**。这是只读检查，不改数据：

```sql
select
  current_setting('server_version_num')::integer >= 150000 as postgres_ok,
  to_regclass('public.questionnaire_versions') as old_versions_table,
  to_regclass('public.research_admins') as old_admins_table,
  to_regclass('public.participants') as old_participants_table,
  to_regprocedure('public.is_research_admin()') as old_admin_check;
```

预期：`postgres_ok=true`，其余四格都有对象名称，不能是NULL。若不是，**停止，把检查结果交给负责人，不要运行初始化脚本来补救。**

再点 **New query**，执行下列只读计数，保存结果；做完迁移后要再查一次，确认旧数据没有减少：

```sql
select questionnaire_version, submission_status, count(*) as old_answer_count
from public.participants
group by questionnaire_version, submission_status
order by questionnaire_version, submission_status;
```

负责人还须核对本文后半部分“2 操作前先核对真实项目”的字段、RLS检查结果，确认现有策略与仓库相符。完成备份、检查并获确认后，才继续下一步。

## 1 本次为什么需要数据库更新

旧项目是 V1.1：一份合并问卷，每人 6 道 DCE，4 个配置各 12 个评分，理解检查题号 Q6/Q7；还必须回答额外的理想配置题。

V2.3 是两份独立问卷：老人版没有 DCE，而有三档偏好与 6 道授权实验；照护者每人 4 道 DCE；两卷均为两个配置各 8 个评分，并增加 100 分分配、注意力题和新的背景信息。

旧表的必填身份字段、非空 DCE 分卷、12 个非空评分列不能直接表示新版老人答卷。为避免将缺失分数填成 0 或更改旧表含义，本次只新增一张主表和几个视图，不删除或修改旧表。

| 新对象 | 作用 |
| --- | --- |
| `survey_v23_submissions` | 每份已提交答卷一行；含版本、类型、渠道、分卷、时间，以及完整的结构化原始 JSON |
| `submit_survey_v23(jsonb)` | 仅服务端能执行的原子提交函数；检查资格、数量、权重、任务配置，处理重复提交 |
| `survey_v23_dce` | 展开 DCE 任务、原始方案 A/B、实际左右位置和最终选择 |
| `survey_v23_ratings` | 每个配置、每个评分项一行，保留题项表述版本 |
| `survey_v23_answers` | 展开小写题号的常规答案和首次理解检查记录 |
| `questionnaire_versions` 的 `V2.3` 行 | 登记新版，默认 `is_active=false`，未经团队验收不开放收集 |

自主授权、权重、三档偏好、随机计划和完整配置快照均完整保存在主表 `payload`，后台提供相应的结构化 CSV。旧 `participants` 等表和 `submit_survey` 函数、历史数据、登录账号与原有白名单均保留。

## 2 操作前先核对真实项目

先确认打开的是现有正式 Supabase 项目，记下项目名称和 Project URL。不要新建项目来替代原项目。

先导出历史答卷和现有数据库结构作为备份。可使用团队已有的备份方式，或先从 Table Editor 导出各旧表 CSV。账号密码、service_role key 不要放入 GitHub、前端或共享截图。

在 SQL Editor 新建查询，先运行以下只读检查。保存结果供团队核对。

```sql
-- PostgreSQL 必须支持 security_invoker 视图（15或以上）。
select current_setting('server_version') as postgres_version;

-- 必要的旧对象是否存在。
select to_regclass('public.questionnaire_versions') as versions,
       to_regclass('public.research_admins') as admins,
       to_regprocedure('public.is_research_admin()') as admin_check,
       to_regprocedure('public.submit_survey(jsonb)') as legacy_submit;

-- 查看旧表字段，和仓库的0001至0004迁移核对。
select table_name,column_name,data_type,is_nullable
from information_schema.columns
where table_schema='public'
  and table_name in ('participants','dce_choices','profile_ratings',
                    'comprehension_checks','survey_responses','custom_config_choices')
order by table_name,ordinal_position;

-- 查看现有RLS是否开启。
select c.relname,c.relrowsecurity
from pg_class c join pg_namespace n on n.oid=c.relnamespace
where n.nspname='public' and c.relkind='r'
order by c.relname;

-- 查看现有策略。
select tablename,policyname,roles,cmd,qual,with_check
from pg_policies where schemaname='public'
order by tablename,policyname;

-- 保留旧版本计数，迁移后再次核对。
select questionnaire_version,submission_status,count(*)
from public.participants
group by questionnaire_version,submission_status;
```

如果必要对象不存在，或真实 RLS 与仓库描述不一致，先停止，不要通过重新执行旧初始化脚本来“修复”。把不一致的检查结果交给负责人确认。

仓库中的安全设计是：匿名用户没有研究表读写权限；登录用户只有在 `research_admins` 白名单中才可读取；写入经 Netlify 函数使用服务端 key 完成。不得为了调通问卷新增“所有人可读写”策略。

## 3 负责人确认后才执行迁移

本次完整 SQL 的交付副本为 `outputs/0005_survey_v23.sql`，代码中的权威来源为 `supabase/migrations/0005_survey_v23.sql`。两者内容一致。

负责人确认的事项：新增上述对象、复用现有管理员白名单、V2.3 与历史表分开存放、新版默认停用、未提交草稿不上传。数据库不会自动删除任何历史数据；本次也不会改写旧 RPC 或旧策略。

确认后，队友在 SQL Editor 中粘贴完整 SQL，整份执行。不要只执行其中一段。SQL 包含事务，发生错误会整体回滚；不要删除出错行后跳过继续。

已有数据库依次执行 0005、0006，不要重跑 0001–0004。若0005已经执行，只补0006；不要在0006之后重跑0005，否则旧函数定义会覆盖新校验。全新测试数据库先按旧说明完成 `supabase/schema.sql`，再依次执行0005、0006。

0006权威文件为 `supabase/migrations/0006_v23_weight_mode.sql`：只把老人排序校验改为“仅排序模式必填，100分模式可不填排序”。不新增或删除表、不覆盖答卷、不改变RLS或函数执行权限。函数定义与预期不同时会中止，不能跳过报错。执行后可用以下只读查询核对条件已更新：

```sql
select position($check$if (w->>'mode'='ranking_only' or jsonb_array_length(w->'ranking') > 0)$check$
  in pg_get_functiondef('public.submit_survey_v23(jsonb)'::regprocedure)) > 0 as weight_mode_updated;
-- 应为true。false时不要正式发放。
```

0005不会把已启用的V2.3改回停用，也不会删除答卷；0006可重复运行。必须按顺序应用，勿自行编辑迁移后覆盖既有定义。

## 4 迁移后先检查权限和对象

```sql
select id,is_active from public.questionnaire_versions where id='V2.3';
-- 第一次应是false。

select to_regclass('public.survey_v23_submissions'),
       to_regprocedure('public.submit_survey_v23(jsonb)');

select relrowsecurity from pg_class
where oid='public.survey_v23_submissions'::regclass;
-- 应是true。

select policyname,roles,cmd,qual
from pg_policies
where schemaname='public' and tablename='survey_v23_submissions';
-- 应只有面向authenticated、调用is_research_admin()的SELECT策略。

select has_table_privilege('anon','public.survey_v23_submissions','SELECT') as anon_select,
       has_table_privilege('anon','public.survey_v23_submissions','INSERT') as anon_insert,
       has_function_privilege('anon','public.submit_survey_v23(jsonb)','EXECUTE') as anon_rpc,
       has_function_privilege('authenticated','public.submit_survey_v23(jsonb)','EXECUTE') as authenticated_rpc,
       has_function_privilege('service_role','public.submit_survey_v23(jsonb)','EXECUTE') as server_rpc;
-- 前四个应false，server_rpc应true。

select relname,reloptions from pg_class
where oid in ('public.survey_v23_dce'::regclass,
              'public.survey_v23_ratings'::regclass,
              'public.survey_v23_answers'::regclass);
-- 三个视图均应包含security_invoker=true。
```
