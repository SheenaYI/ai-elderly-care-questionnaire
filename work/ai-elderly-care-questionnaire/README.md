# 智能养老AI监测系统配置偏好与采纳意愿调查

一个用于**学术研究**的在线问卷与离散选择实验（DCE）平台，研究人们对 AI 养老监测系统在不同
信息共享与监测配置下的偏好，以及对安全、隐私与老人自主性的感受。

本项目是大学生创新创业训练计划科研项目的一部分。研究设计与问卷文本以
《智能养老AI监测_问卷初稿与DCE实验设计_V1》（V1.0）为**唯一权威来源**，
代码严格按该文件实现，不擅自改动任何配置、配对或题目措辞。

> **当前状态：原型开发中，尚未获得正式数据收集许可。**
> 在完成伦理审查与 Pilot 试填之前，本站**不得**作为正式发放渠道。
> 详见下方「当前状态」一节。

## 网站有哪五个公开页面

| # | 路由 | 页面 | 内容 |
|---|---|---|---|
| 1 | `/` | 参与研究（首页） | 研究简介、参与须知、开始填写入口 |
| 2 | `/experience` | 情景体验 | 以统一情景演示不同监测配置的运行方式（研究用预设模拟） |
| 3 | `/about` | 研究介绍 | 研究背景、研究问题与研究方法；只陈述测量内容，不陈述预期结果 |
| 4 | `/privacy` | 隐私与知情同意 | 数据如何被收集、保存与访问，参与者的退出与删除权利 |
| 5 | `/questionnaire` | 问卷 | 五个模块的完整填写流程（`/questionnaire/:step` 为分步地址） |

另有一个**不面向参与者**的研究管理后台 `/admin`：它被懒加载、不出现在任何导航中，
需要管理员身份才能访问。

路由定义见 `src/app/router.tsx`，导航项见 `src/components/layout/SiteNav.tsx`。

## 问卷有哪五个模块

| 模块 | 名称 | 内容 |
|---|---|---|
| 一 | 知情同意与身份信息 | Q1 知情同意；Q2–Q5 年龄范围、答题身份、AI 养老监测设备了解程度、照护老人经历 |
| 二 | 统一情景与理解检查 | 统一情景说明（所有方案基础异常识别与报警能力相同）；Q6、Q7 两道理解检查，答错时展示正确解释 |
| 三 | DCE 配置选择 | 随机分配 A 卷或 B 卷，各 **6 道**任务；每题从两个完整配置中选择更愿意长期采用的一个 |
| 四 | 随机配置感知评价 | 每人按平衡规则获得 **4 个不同配置**，每个配置回答 **12 个**评分题（安全感 S1–S3、隐私担忧 P1–P3、自主感 A1–A3、采纳意愿 I1–I3） |
| 五 | 总体评价 | Q8 总体采纳意愿；Q9 最担心的问题；Q10 开放性建议（可跳过） |

实验操纵三个属性：**X1 共享层级**（0 仅摘要信息 / 1 详细原始数据）、
**X2 共享对象**（0 仅指定子女 / 1 指定子女及授权养老服务机构）、
**X3 详细监测方式**（0 异常时详细监测 / 1 全天持续详细监测；V1.0 中该属性亦称「监测时长」）。
三个属性组合出 8 种配置 C1–C8。

## 技术栈

| 层 | 选型 |
|---|---|
| 前端框架 | React 18 + TypeScript |
| 构建工具 | Vite 5 |
| 样式 | Tailwind CSS 3（深森林绿 / 鼠尾草绿 / 奶油白，面向中老年参与者上调正文字号） |
| 路由 | React Router 6（`BrowserRouter`，部署时需 SPA 重写） |
| 状态管理 | Zustand（问卷状态 + 本地草稿持久化） |
| 表单校验 | Zod（前后端共用同一套校验规则：前端提交前自检，服务端独立复核） |
| 后端 | Supabase（PostgreSQL + Auth + Row Level Security） |
| 服务端接口 | `api/` 目录下的 Serverless Function（Vercel 自动识别）：提交与 CSV 导出 |
| 测试 | Vitest + jsdom（7 个测试文件，180 个断言，含页面渲染、草稿持久化与视频降级测试） |
| 图标 | lucide-react |

> 说明：表单状态由 Zustand 统一管理，校验全部由 Zod 完成（前后端共用同一套规则），
> 因此本项目**没有**引入 react-hook-form 等表单库，避免不必要的依赖。

## 快速开始

```bash
npm install --cache "$PWD/.npm-cache"   # 本机 npm 全局缓存权限异常的替代方案
npm run dev                              # 启动开发服务器，默认 http://localhost:5173
npm test                                 # 运行测试
```

不配置任何环境变量也能启动：此时平台处于 **Demo 模式**，问卷可以完整填写，
但提交后的数据**只留在你自己的浏览器里，不会写入云端**。
需要真实提交时，把 `.env.example` 复制为 `.env.local` 并填入 Supabase 配置；
环境变量的公开/私有划分见 [docs/SETUP.md](docs/SETUP.md) 第 5 节。

其它常用命令：`npm run build`（含类型检查）、`npm run preview`、`npm run typecheck`。
完整说明见 [docs/SETUP.md](docs/SETUP.md)。

## 安全与伦理声明

- **本研究仅用于学术研究。** 不用于任何商业用途，不用于真实养老监控。
- **情景体验全部是预设模拟。** 页面中的跌倒事件、时间点、监测画面与通知均为前端预设状态，
  不代表真实的 AI 识别、报警或视频记录结果。
- **不开启摄像头、不采集音视频。** 平台不请求摄像头或麦克风权限，不进行任何真实监控，
  不连接任何真实监测设备；数据库中也不存在音视频字段。
- **参与完全自愿，可随时退出。** 不要求提供真实监控视频、姓名或身份证号；
  采集的是匿名标识与作答内容。
- **不编造研究信息。** 研究团队尚未确认的内容（所属单位、伦理审批编号、研究联系人、
  数据保存期限、可访问数据的人员范围、退出与删除申请方式、预计填写时间）在界面上
  一律显示为 `[待填写：…]` 占位符，绝不填写臆测内容。
- **不影响研究结果的表述。** 预设研究假设（H1–H3）不出现在任何参与者可见页面中，
  问卷措辞保持中立。
- **隐私担忧题的记分方向是固定的。** P1–P3 分数越高表示隐私担忧越强，
  数据分析时**不得**反向计分为「隐私满意度」。

## 当前状态

已完成（原型阶段）：

- 五个公开页面与 `/admin` 路由，右侧固定导航、移动端折叠菜单、深链接可刷新
- 研究内容的单一数据来源（`src/data/`）：C1–C8 配置、T01–T12 任务表、
  Q1–Q10 问卷文本、12 个量表题、A/B 两卷分卷规则
- 随机化引擎：随机分卷、题序随机、每题左右随机、每人 4 配置的平衡分配，
  且随机化结果在一次会话内保持稳定（刷新与返回上一题都不会重新随机）
- 数据校验规则（Zod，前后端共用）与设计完整性自查
  （每卷 6 题、差分矩阵秩 = 3、属性水平平衡、每题 2 个属性变化）
- 本地草稿持久化与恢复、Demo 模式与真实提交模式的明确区分
- 情景体验与模拟事件脚本、视频缺失时的占位降级
- 数据库结构与安全策略：`supabase/schema.sql` 及三个迁移（建表、RLS 策略、权限回收），
  含 DCE 长表视图 `analysis_long` 与单事务写入函数 `submit_survey()`；
  匿名角色对全部表**无任何权限**
- 服务端接口：`POST /api/submit-survey`（唯一写入通道，服务端权威校验）与
  `GET /api/admin/export`（需登录 + `research_admins` 白名单，导出带 BOM 的 CSV）
- 研究管理后台：邮箱密码登录、统计面板、上线前检查、逐题选择分布与导出入口
- 测试：7 个 Vitest 测试文件、180 个断言（设计完整性、随机化、数据一致性、校验规则、
  草稿持久化与恢复、
  页面渲染），`npm run typecheck` 与 `npm test` 当前均通过

**正式数据收集之前仍必须完成：**

1. **Supabase 凭据尚未配置。** 需要在部署平台补齐项目 URL、anon 公钥（公开）与
   `SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`（仅服务端；模板见 `.env.example`），
   并执行数据库 schema 与 RLS/权限迁移、把管理员邮箱写入 `research_admins` 白名单、
   关闭 Auth 的公开注册。在配置完成前，站点只能以 Demo 模式运行，数据不会写入云端。
2. **研究团队信息尚未填写。** `src/data/placeholders.ts` 中 9 个字段仍为
   `[待填写：…]`，包括所属学校或研究单位、研究负责人、研究联系人及邮箱、
   伦理审批编号、预计填写时间、数据保存期限、可访问数据的人员范围、
   退出与数据删除申请方式。
3. **伦理审查尚未完成。** 需取得所在单位伦理审查意见（含编号，或"无需编号"的书面意见）。
4. **Pilot 试填尚未完成。** 按 V1.0 要求，需先进行 3–5 人认知访谈，

   据此检查属性理解、选择分布、位置效应与量表质量，并修订后复测。
5. **部署配置文件尚未创建。** 仓库中还没有 `vercel.json`（或 `netlify.toml`）；
   React Router 的 SPA 重写必须随之补齐，`/admin` 与问卷深链接才能直接访问。
